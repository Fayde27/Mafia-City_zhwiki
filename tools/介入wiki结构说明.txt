> 最后更新：2026-06-23

---

## 一、这是什么

一个展示「豪杰/英雄阵容搭配方案」的页面工具。形态参考《豪杰特报》攻略图：每套搭配由 **3 个豪杰 + 各自的加点/武器/战徽 + 一段实战解说** 组成。

**核心交互模式（请务必理解）：**

- **方案是「人工配好的」，不是玩家自由组合算出来的。** 我们游戏没有「毕业数值」体系，属性也不好计算，所以**不要做战力计算器**。运营会预先录入一批搭配方案，工具只负责「展示 + 让玩家检索」。
- **玩家的「自定义」= 筛选检索**，不是自由搭配。两个入口：
  1. 按**队伍类型**筛（飞车党 / 暴徒 / 枪手…）
  2. 按**单个豪杰**反查（「我抽到玉藻前，能玩哪些搭配」）→ 列出所有包含该豪杰的方案。这是玩家最高频的需求。

---

## 二、展示规格（一张搭配卡长什么样）

完全对照《豪杰特报》原型图。一张卡包含三部分：

### 2-1 卡片顶部
- **队伍类型标签**：如「飞车党搭配 / 暴徒篇搭配 / 枪手搭配」
- **角标**：`NEW` / `HOT` 等（人工维护，可多个）
- **更新日期**：显示在右上角，如「更新 2024/11」（纯展示，让玩家自己判断新旧）

### 2-2 中间 = 3 个豪杰位，每位四行

| 行 | 展示内容 | 是否可点击 |
|----|---------|-----------|
| **豪杰** | 头像 + 名字（夜雀 / 老乌鸦 / 玉藻前） | ✅ 点击 → 豪杰详情页 |
| **加点** | 加点方向图标 + 文字（全技术 / 全体魄 / 全防护）+ 称号（执法者 / 蝰蛇 / 杀人蜂…） | 否（纯文本） |
| **武器** | 武器名 + 武器图标 + ⭐ 武器技能说明文字（如「队伍内每有一位智谋豪杰，技术+7…」） | ✅ 点击 → 武器详情页 |
| **战徽** | 战徽图标 + 词条列表（豪杰技术 / 豪杰特殊伤害 / 豪杰伤害 / 飞车属性…） | ✅ 点击 → 战徽详情页 |

### 2-3 卡片底部「热门」解说区
- 一段富文本实战说明：技能联动 + 打法 + 数量建议（如「放入少量武装越野、火炮，数量建议 1000 左右」）
- 文中可能嵌豪杰/技能链接

> 「可点击」的元素，先用占位链接（如 `#` 或 mock URL）即可，最终真实 URL 由我方在并入时提供。

## 三、页面结构

| 页面 | 内容 |
|------|------|
| **列表/总览页** | 展示所有搭配卡 + 两个筛选入口（队伍类型、豪杰）；卡片按「置顶 → 手动排序」排列，**不按时间倒序** |
| **详情页（可选）** | 单套搭配的大图展示；若列表卡片本身已够大、信息完整，可不做独立详情页 |

排序规则：`isPinned`（置顶）优先 → `sortOrder`（手动序号）。曝光完全由人工 `badges` + 排序控制，**不做自动过期、不按日期自动排序**。

## 四、数据契约（请照此 mock）

> **最重要的一条：mock 数据必须严格按下面的 JSON 形状来造。** 这样我方接入真实接口时，只需替换数据来源，你的解析/渲染代码一行不用改。
> 真实数据接口由我方在并入阶段提供；下面的字段结构是最终格式，路径仅为示意。

### 4-1 搭配方案（一张卡）

```jsonc
{
  "id": "tb_001",
  "slug": "feiche-yuzaomae",
  "title": "飞车党搭配",
  "teamType": "feiche",            // 队伍类型，筛选用: feiche/baotu/qiangshou...
  "characterKind": "haojie",       // haojie(豪杰) 或 hero(英雄)
  "updateDate": "2024/11",         // 右上角展示
  "badges": ["NEW", "HOT"],        // 角标，人工维护
  "isPinned": false,
  "sortOrder": 0,
  "hotText": "夜雀优先升级 5 技能「讯鸟不鸣」，搭配老乌鸦的「海盗王之怒」……",  // 富文本/HTML
  "slots": [                       // 3 个豪杰位
    {
      "haojie":   { "id": "char_yz", "slug": "yezque", "name": "夜雀", "icon": "https://.../yezque.png" },
      "pointHint": "全技术",        // 加点方向
      "title":     "执法者",        // 称号
      "weapon":   { "id": "eq_w01", "slug": "zhifazhe", "name": "执法者", "icon": "https://.../w01.png",
                    "skillNote": "队伍内每有一位智谋豪杰，技术+7，豪杰技术+7，智谋装备时技术额外+7" },  // ⭐ 武器技能说明
      "warbadge": { "id": "eq_b01", "slug": "warbadge-x", "name": "战徽X", "icon": "https://.../b01.png",
                    "stats": ["豪杰技术", "豪杰特殊伤害", "豪杰伤害", "飞车属性"] }  // 战徽词条
    }
    // ... 共 3 个
  ]
}
```

### 4-2 列表接口返回（示意）

```jsonc
// 按队伍类型筛: ?teamType=qiangshou
// 按豪杰反查:   ?haojieId=char_yz
{ "data": [ /* 上面的搭配方案对象数组 */ ] }
```

> 「按豪杰反查」= 返回所有 `slots` 里包含该 `haojieId` 的搭配。你只管按返回的数组渲染；过滤逻辑在接口侧，你前端也可以在拿到全量后自行 filter（mock 阶段建议这样做）。

### 4-3 选择项数据（mock 用）

工具里需要「可选的豪杰 / 武器 / 战徽列表」（如果你也做录入/演示界面）。每项形状：

```jsonc
// 豪杰
{ "id": "char_yz", "slug": "yezque", "name": "夜雀", "icon": "https://.../yezque.png" }
// 武器 / 战徽
{ "id": "eq_w01", "slug": "zhifazhe", "name": "执法者", "icon": "https://.../w01.png", "rarity": 6 }
```

## 五、通用要求

1. **不做战力/属性计算**——只展示人工配好的方案。
2. **响应式**：原型图是竖向长图，手机端是主要场景，确保移动端可读、可点。
3. **样式中性、可替换**：用普通的卡片/表格布局即可，**不用纠结配色和字体**——并入时我方会统一套用网站主题样式。你只要保证**结构清晰、信息分区和原型图一致**。
4. **更新日期、badges、排序全是数据字段**，由内容决定，不要硬编码。
5. **所有图片用数据里的 URL 直接渲染**，不用自己存图。
6. **不要把整套搭配做成一张图片**——必须是结构化的 HTML 元素，这样豪杰/武器/战徽才能各自点击跳转。

## 六、技术建议（不强制）

- 框架：用 **React / Next.js** 最理想（我方主站是 Next.js，技术一致并入最顺）。若你更熟其他栈也行，但请保证组件/逻辑可移植、不依赖特定后端框架。
- 数据层：把「取数据」抽成一个独立函数/模块（如 `fetchTeamBuilds()`），mock 阶段返回本地 JSON，接入时只改这一处。
- 不要内置自己的数据库/后端服务；数据一律走「接口返回 JSON」这一条路径。
